## 2. Server（`server/`）审计

### 2.1 结构与依赖
- 单 crate binary：`weavine-server` v1.1.0（`server/Cargo.toml:2-3`）。
- 通过 `weavine = { path = "../src-tauri", default-features = false, features = ["sqlx"] }` 复用 `weavine_lib::models`（`server/Cargo.toml:17`，`src-tauri/Cargo.toml:9` 定义 `[lib] name = "weavine_lib"`）。
- Handler 拆 24 文件（auth/contact/event/note/.../sync/ocr/voice/storage/...），business 仅 `archive_sweep`。
- **没有全局 auth middleware** — 每个 handler 第一行 `let auth = extract_auth(&headers, pool.as_ref()).await?;` 手取用户，漏调即 BOLA。`log_requests` 注释（`main.rs:218-219`）也只说 "print before auth"，**没有 auth 层统一防线**。

### 2.5 High/Med 风险详述

#### A. `/files/*key` 无 auth — media 任何人可读 [High]
- **位置**：`server/src/main.rs:154` 路由 + `server/src/handlers/storage.rs:122-136` `serve_file`。
- **证据**：路由注册处无 `.layer` 鉴权；handler 签名只接受 `Path<String>` + `Extension<Arc<dyn Storage>>`。`media::get_blob`（`media.rs:235-253`）做了 user_id 校验后 302 到 `/files/...`，但重定向后的目标路径没有 auth 包装。`storage_key` 是 UUID-ish 但不到密码强度，可枚举。
- **修复方向**：给 `/files/*key` 加 middleware 调 `authorize_storage_key(headers, path)`，从路径 prefix `{user_id}/{kind}/...` 抽出 user_id 跟 JWT 比对；或把 `serve_file` 改成接受 `headers` + 在 `Storage::get_response` 前查 DB。

#### B. `DefaultHasher`（SipHash, 64-bit）用于 refresh/reset token 哈希 [High]
- **位置**：`server/src/handlers/auth.rs:178-184` 函数定义 + 9 处调用（`auth.rs:465, 561, 675, 713, 754, 921, 996` 等）。
- **证据**：
  ```rust
  fn blake_hash(s: &str) -> String {
      use std::collections::hash_map::DefaultHasher;  // SipHash, 64-bit, NOT crypto
      ...
      format!("{:016x}", h.finish())                  // 16 hex chars = 64 bits
  }
  ```
  refresh_token 和 password_reset_token 的 `token_hash` 列都依赖此函数。SipHash 输出 64 位且 seed 在进程启动时随机 — 攻击者拿到 1 个 token hash 可以验证其它 token 是否"同一进程生成"；且 64 位空间在 2^32 尝试下 50% 碰撞。
- **修复方向**：换 `sha2::Sha256` 输出 32 字节 hex (64 字符)，同步加 migration 把 `token_hash` 扩到 64 字符（迁移时双写老 hash）。

#### C. `/api/api_keys/:id/plaintext` 永久可重读明文 key [High]
- **位置**：`server/src/handlers/api_key.rs:130-151`。
- **证据**：`reveal` handler 从 DB 拉 `key_ciphertext` + `key_nonce` 后用 master key + user_id AAD 解密，返回明文。响应没有任何一次性 token 机制 — 攻击者只要拿到 user 任何短期 token（如 api_key 本身就是），就能反复 GET 这个 plaintext 端点把 key 拿出来。
- **修复方向**：把 `reveal` 改为 (1) 接受 `created_at + 一次性 token` query，只有 `created_at < now - 60s` 才允许；或 (2) 完全删除 `reveal` 端点，只在 `create` 响应里返 plaintext + 设 flag 表示"已读"；或 (3) 强制要求重新输入密码 + 邮件 OTP。

#### D. `CorsLayer::permissive()` 生产放行所有跨域 [High]
- **位置**：`server/src/main.rs:182`。
- **证据**：`.layer(CorsLayer::permissive())` — 接受任何 origin / method / header。
- **修复方向**：改为 `.layer(CorsLayer::new().allow_origin([...]).allow_methods([...]).allow_headers([...]).allow_credentials(true))`，并加 `WEAVINE_ALLOWED_ORIGINS` env var 让 deploy 时配置。

#### E. (前端，详见 §3) 全局快捷键 `\` 双绑 [High]

#### F. (scripts，详见 §4) `weavine-web` 命名漂移 [High]

#### G. (scripts，详见 §4) `deploy-web.sh:51` 单引号嵌入变量不展开 [High]

#### H. `search.rs` 6 处 `unwrap_or_default()` 静默吞错 [Med]
- **位置**：`server/src/handlers/search.rs:34, 44, 57, 70, 78, 88`。
- **证据**：6 条 `fetch_all(&*pool).await.unwrap_or_default()` 全部用 `unwrap_or_default()`。任一子表 SELECT 失败（比如 DB 短暂断连），整次搜索结果静默变空，前端拿到空数组以为"没有匹配项"。
- **修复方向**：用 `let rows = ... .map_err(|e| { eprintln!("[search] contacts: {e}"; (StatusCode::INTERNAL_SERVER_ERROR, ...) })?;` 模式；或者在请求顶层累加 error，第一个错误就 500。

#### I. `contact::list` N+1 query [Med]
- **位置**：`server/src/handlers/contact.rs:88-99`。
- **证据**：`for contact in rows { let tags = sqlx::query_as::<_, Tag>(...).bind(&contact.id).fetch_all(...) }` — 每行 contact 发 1 条 tag 查询。20 个 contact → 21 条 query。
- **修复方向**：改成两阶段：(1) 主查询拿 contact 列表，collect 所有 `contact_id`；(2) 单条 `SELECT tag.* FROM tag t JOIN contact_tag ct ON ct.tag_id = t.id WHERE ct.contact_id = ANY($1) AND t.deleted_at IS NULL`；(3) HashMap<contact_id, Vec<Tag>> group by id。

#### J. 测试覆盖严重不足 [Med]
- **现状盘点**：
  - `rate_limit.rs` — 4 unit test。
  - `auth.rs:1073-1114` — 4 unit test（blake_hash, reset_token, client_ip）。
  - `sync.rs:559-627` — 4 unit test。
  - `event.rs:808-1076` — 3 `#[sqlx::test]`。
  - `reminder_dispatcher.rs:44-121` — 2 `#[sqlx::test]`。
  - `email/mod.rs:133-148` — 1 log sender test。
  - `keep_in_touch_server.rs:143-170` — 4 unit test（纯函数）。
- **缺测试的模块**：`contact/media/project/action/interaction/tag/setting/note/api_key/quick/ocr/voice/graph/archive` 整套 handler + `sync::push` 的复杂 upsert 逻辑（只测了列名校验）、SQLi 防御。
- **没有 `tests/` 目录**，没有集成测试。
- **修复方向**：给 `sync::push` 加 `#[sqlx::test]` 覆盖 (1) valid upsert, (2) conflict 路径, (3) SQLi 注入尝试被 `is_safe_column_name` 拦截；给 `auth::register/login/refresh` 加 integration test；给 `contact::list` 加 N+1 benchmark。

#### L. `keep_in_touch_server` 全表扫描 + 单 contact 独立 tx [Med]
- **位置**：`server/src/keep_in_touch_server.rs:80-141`。
- **证据**：`SELECT id, importance, last_interaction_at, keep_in_touch_cadence_days FROM contact WHERE deleted_at IS NULL` 无 LIMIT，循环里每个 contact 单独 `pool.begin()` + DELETE + INSERT，1 万 contact 跑 ~10 分钟。注释承认了"scan sequential at PG planner's discretion but bounded by user count"。
- **修复方向**：拉全表到内存后按 `user_id` 分组；每 user 一个 tx；加 `LIMIT 1000 OFFSET 0` 循环到空；可选 `pg_advisory_lock` 串行化避免多实例重复。

#### 其他发现（不重复展开）
- **`/api/diagnostic/startup` 公开泄露 DB 状态和版本**（`handlers/diagnostic.rs:22-34` + `main.rs:91`）— 建议加 `X-Service-Key` 或 JWT auth，或移到 `/internal/diagnostic/startup` 路径下。
- **`forgot_password` 与 `register` 撞库策略相反**（`auth.rs:507-509` register 返 "email already registered"，forgot-password 故意返 ok 防撞库）— 建议统一策略。
- **`extract_auth_with_device` 在 API key 路径下让 `set_config` 写空 device_id**（`auth.rs:247-265`）— API key 路径返 `(user_id, "")`，下游 sync trigger 用 `current_setting('app.current_device_id', true)` 可能 NULL 写库。建议对 API key 路径不返 device_id，改返 `Option<String>`。
- **api_key 解密后未做 `wvk_` 前缀校验**（`api_key.rs:146-149`）— corruption 走错路。
- **`voice.rs:213-215`** 硬编码 `"—"` 丢失 pcm 样本数日志。
- **`storage.rs:118` `Ok(resp.body(...).unwrap())`** — `Response<Body>` 构造永不出错，可删 `.unwrap()`。
- **master_key 长度不匹配时 runtime panic**（`api_key_crypto.rs:37-42`）— 启动时校验而非首次调用。
- **JWT keys 默认走仓库内 `jwt-private.pem`/`jwt-public.pem`**（`auth_keys.rs:19-21`）— 静默 fail-mode，prod 应强制 env var。
- **`change_log_pruner` 启动前先 30s sleep**（`main.rs:197-198`）— 用 `MissedTickBehavior::Skip` 改写。

### 3.1 入口与路由

### 3.2 状态管理
- 服务端缓存：react-query 单一 QueryClient（`lib/adapter/index.ts:62-72`，全局默认 `staleTime: 30_000`、`refetchOnWindowFocus: true`、`retry: 1`）。
