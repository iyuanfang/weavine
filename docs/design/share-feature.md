# 产品设计：笔记 & 日程分享

状态：设计稿 v1 · 2026-10-08
一句话：**每一次分享，都是织遇的获客落地页；每一个日程邀请，都是好友协作的入口。**

---

## 0. 与既有决策的关系

此前否掉的是"好友互加"的社交图谱——织遇的人脉是私人的，用户互加无意义。
本设计做的是**按内容的点对点分享**：一条笔记、一个日程的临时出口，分享即链接，撤销即失效。
不建社交关系，不加好友体系，不改变"数据在你手里"的单人产品结构。

## 1. 两个目标，两套机制

| 目标 | 机制 | 传播/协作逻辑 |
|---|---|---|
| 社交传播 | **分享卡 + 公开页** | 收件人打开的每个分享页都带织遇品牌与注册 CTA——分享即获客 |
| 好友协作 | **日程邀请 + 回应** | 对方不用装 App，点链接就能回应"参加/不去"，回应回到你的日程里 |

核心洞察：**日程邀请是天然的一对多传播**（一个日程发到一个群=几十人看到），笔记分享是天然的内容传播（好笔记值得转发）。两者都把"织遇"带到陌生人眼前。

## 2. 分享的三个出口

| 出口 | 形态 | 场景 |
|---|---|---|
| 微信好友/群 | 链接卡（标题+摘要+织遇品牌） | 点对点发送、拉人参会 |
| 朋友圈 | **图片卡**（服务端渲染 PNG，角落带小程序码/二维码） | 晒读书笔记、晒活动——朋友圈文字不能带链接，图片是唯一通道 |
| 公开链接 | `weavine.com/s/<token>` 移动端优先的公开页 | 所有场景的落地 |

复用已有资产：图片卡直接走 quickcrat 渲染管线（同款品牌行+二维码），不重造。

## 3. 笔记分享

**入口**：笔记详情页右上「分享」→ 选出口。

**公开页形态**（移动端优先）：
- 顶部：织遇品牌行（logo + 名字）——这是获客位，不可关闭
- 正文：标题 + 内容（Markdown 渲染）+ 图片
- **默认剥离**：关联的联系人/标签不出现在公开页（保护第三方隐私——笔记里链接了张三，不代表张三同意出现在你的分享里）
- 底部 CTA：「我用织遇记录人脉与灵感」+ 二维码 → landing

**权限与控制**：
- 分享是**按条开关**的：默认私密，点分享才生成 token；随时撤销，链接立即失效
- 链接 = 不可猜的 token（22 位）；不设密码（V1 保持零摩擦）
- 分享页显示实时内容（编辑后同步），撤销即下线——简单可预期
- 查看次数对主人可见（轻反馈：有人看 → 更愿意分享）

## 4. 日程分享（协作的核心）

日程的分享不是"晒"，是**邀请**——这是协作的真入口。

**公开邀请页**：
- 日程卡：标题、时间、地点、说明（主人可选字段公开：默认隐藏备注，只公开时间地点标题）
- **回应区（无需注册）**：输入称呼 + 「参加 / 可能 / 不去」→ 回应直达主人的日程详情
- 「加入我的日历」按钮：下载 .ics，一键进对方日历——**不装织遇也能协作**
- 日程**变更自动生效**：改时间/地点，公开页即时更新（V2 加"已变更"推送提醒回应者）
- 底部同笔记：品牌行 + CTA

**主人侧**：
- 日程详情显示回应列表（称呼 + 选择 + 时间）
- 一个日程可生成一个邀请链接，发群里的都是同一个链接，回应汇总回来

**这就是"好友间协作"的 V1**：零安装、零注册、单向发起 + 对方回应。共同编辑（对方改你的日程）V1 明确不做——隐私产品先给控制权。

## 5. 协作演进路线

| 期 | 能力 | 说明 |
|---|---|---|
| V1 | 只读分享 + 日程回应（匿名+称呼）+ ics | 零账号摩擦 |
| V2 | 共享日程的"提议改期"（对方提议新时间，主人确认）；笔记分享页的**留言**（访客留言，主人可见） | 协作有了往返 |
| V3 | 两个织遇用户间的"共享日程"（双方都可编辑，各存各的库，同步合并）——真正双端协作，但依赖 V1.8 的同步底座 | 等同步稳定性验证后再做 |
| 不做 | 社交信息流、好友动态、公开主页——违背单人私密产品定位 | — |

## 6. 隐私原则（CRM 的底线）

1. **按条分享，默认私密**——不存在"账号级公开"
2. **第三方保护**：分享页永不渲染关联联系人（正文里主人自己写的名字除外，那是主人的责任）
3. **可撤销**：token 失效 = 立即 404；日程邀请可随时关闭回应
4. **最小默认**：日程分享默认只带 时间/标题/地点，备注和附件默认不公开
5. 查看计数只对主人可见，访客完全匿名（不留 IP/身份）

## 7. 系统概要（不展开实现）

- 服务端新表 `share_link`：token、entity_type、entity_id、owner、created_at、revoked_at、view_count
- 公开页：服务端直出轻量 HTML（无登录、移动优先、SEO 友好），`/s/<token>`
- 图片卡：复用 quickcrat 的 headless 截图管线，出 PNG
- RSVP：`share_rsvp` 表（token、称呼、选择、时间）；日程详情拉取回应列表
- 无账号访问 → 公开接口必须限流（按 IP），防爬防刷

## 8. 传播闭环（和已有资产的咬合）

```
用户分享笔记/日程
  → 收件人打开公开页（织遇品牌行 + CTA）
  → 扫码 → landing（现有 QR-G/H 分享卡同款转化路径）
  → 注册 → 新用户再分享 → 循环
```

- quickcrat 分享卡管"品牌曝光"（朋友圈），本功能管"内容分发"（点对点）——两条线互补
- 月度人脉报告（bookmark 设计里 V3 的素材）未来也走这套分享底座

## 9. 成功指标

- 分享率：每周分享 ≥1 次的活跃用户占比（目标 15%+）
- 分享页 → landing 点击率（>8%）、→ 注册转化
- 日程邀请回应率（>30% 说明协作有价值）
- 撤销率（过高说明用户对隐私不安，需要复查默认值）

## 10. 待定决策（默认已选）

| 决策 | 默认 | 备选 |
|---|---|---|
| 分享页域名 | www.weavine.com/s/… | 短域 s.weavine.com（后续可换，token 不变） |
| 链接有效期 | 永久（直到撤销） | 可选 7 天/30 天过期（V2 加选项） |
| 日程回应身份 | 匿名 + 自填称呼 | 要求登录（摩擦大，不推荐 V1） |
| 笔记分享形态 | 实时内容 | 分享时冻结快照 |
