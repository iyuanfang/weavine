# 产品设计：微信原生传播与转化（分享功能深化）

状态：设计稿 v1 · 2026-10-08
上游：docs/design/share-feature.md（分享底座）
一句话：**在微信里，分享要有用，转化要无声**——收件人先得到价值，织遇顺带被看见。

---

## 1. 价值设计：三方都得利，传播才发生

传播不是"加分享按钮"，是让每次分享对**三方**都划算：

| 角色 | 得到什么 | 失败模式（要避免） |
|---|---|---|
| 分享者 | **组局成功**（有人回应）、**社交货币**（晒得出手的好内容）、**帮忙**（转给真需要的朋友） | 分享出去像广告 → 伤面子，不再分享第二次 |
| 收件人 | 内容/邀请**本身有用**：看清时间地点、一键进日历、一键回应 | 被逼注册才能看 → 直接关闭 |
| 织遇 | 品牌曝光 + 注册转化 | CTA 太吵杀死分享循环 |

**核心楔子：组局。** "周六吃饭谁来了？"是微信里真实的高频痛点（群里接龙混乱、私聊统计麻烦）。日程邀请页天生就是**组局工具**——主人发一个链接进群，所有人点开回应，名单自动汇总回主人日程。这一条同时满足：有价值（组织工具）、能传播（一次分享触达 5–30 人）、回 CRM（组完局自动成了"互动记录"）。

**笔记分享的楔子：转给对的人。** 看到好文章/好想法转发给朋友是微信日常——织遇笔记分享页把这件事做得体面（干净排版 + 织遇品牌），收件人顺势认识织遇。

## 2. 微信的物理规则（设计必须服从）

| 场景 | 形态 | 设计约束 |
|---|---|---|
| 转给好友/群 | **链接卡**（标题+摘要+缩略图） | 卡片文案就是广告位：标题按收件人视角写 |
| 朋友圈 | **只有图片**（链接会被压流） | 图片卡（quickcrat 管线出 PNG）+ 角落二维码 |
| 卡片内点开 | 微信内置浏览器 H5 | 页面移动优先、秒开、不能唤起下载 |
| 身份 | 公众号网页授权（需认证服务号） | 见 §4 身份阶梯 |
| 分享卡片自定义 | JS-SDK（需认证公众号 + 安全域名） | 未接前用页面 `<title>`/`og:image` 自动生成——标题工程照做 |

**卡片文案工程**（收件人视角，不是主人视角）：
- 日程：`张三邀请你参加「产品沙龙」 · 周六 14:00 · 滨江咖啡`
- 笔记：`我整理的人脉笔记：第一次拜访该聊什么`
- 兜底规则：`<title>` 标签直接按这个格式出（自动卡片也能看），接 JS-SDK 后再精细化

## 3. 不强制注册的引导设计：身份阶梯

原则：**匿名能完成一切阅读与回应；想"被记住/想保存/想创建"时才引导升级身份**。每一级都给即时价值，不白要信息。

```
L0 匿名浏览        打开分享页：全部内容可见，无任何遮挡
L1 昵称回应        日程邀请：填称呼 + 参加/不去（10 秒，无账号）
L2 微信一键登录    公众号网页授权（snsapi_userinfo）→ 头像昵称openid
L3 手机号绑定      通知触达（日程变更、提醒）
L4 完整账号        创建自己的内容 → 自然成为织遇用户
```

**转化时机（在价值时刻引导，而不是入口拦人）**：
- 回应后："想让我记住你的选择、日程变更时提醒你？→ 微信一键登录"
- 想收藏分享的内容："把这篇小说存进你的织遇 → 登录"
- 想创建自己的邀请/笔记："创建你的 → 登录"
- 底部常驻：柔和的一行"织遇 · 管理你的人脉与日程"（品牌位，非按钮）

**外部依赖与降级**：
- L2 微信网页授权需要**认证服务号**（企业/个体户主体，个人主体无法认证）——未具备时，L2 用**手机验证码登录**替代（无外部依赖），具备后加微信一键（转化率更高）
- 分享卡片自定义（JS-SDK）同样依赖认证服务号 + 安全域名；未具备时靠 `<title>` 工程
- 认证服务号还有第二重价值：**模板消息**——"日程明天开始""小鸟想去见张三了"可以走微信推送，微信同时成为**留存渠道**而不只是传播渠道

## 4. 小程序：现在不做，但留好门

**能解锁的**：原生分享卡（分享出去是小程序卡片，体验最佳）；微信静默登录（wx.login，零注册）；订阅消息（微信内提醒）；"用完即走"的心智。

**成本**：独立技术栈（Taro/原生）；微信审核与类目资质（涉及"笔记/日程"类目，个人主体受限，最好企业主体）；两套前端的状态同步。

**触发条件（满足任一再启动）**：
1. 分享页 H5 的注册转化率稳定 >5%，且流失分析显示"想要小程序"是主要反馈
2. 需要微信内提醒（订阅消息）作为核心留存渠道时
3. 单月分享页 UV > 1 万（摊得开开发成本）

**现在要做的准备**（零成本）：所有分享页 H5 顶部预留"在小程序中打开"的协议占位不做，但**服务端 share API 按 openid 预留字段**；卡片标题/缩略图工程先做（对 H5 和小程序都有效）。

## 5. 分享页的转化设计（价值优先的排版）

```
┌─────────────────────────┐
│ 张三邀请你参加「产品沙龙」 │  ← 内容就是头版，无横幅无遮挡
│ 周六 14:00 · 滨江咖啡     │
│ [参加] [可能] [不去]      │  ← 10 秒完成价值动作
│ ─────────────────────   │
│ 已回应：李四、老王、我 +5  │  ← 社交证明（仅日程）
│ ─────────────────────   │
│ 织遇 · 管理你的人脉与日程  │  ← 品牌行（柔和）
│ [微信登录，记录你的每一次] │  ← 转化位，仅此一处
└─────────────────────────┘
```

- 价值动作永远在第一屏；转化位永远在价值完成之后
- 二次分享钩子：回应完成的页面出现"组织你自己的活动 →"（把收件人变成下一个分享者）
- 不做：弹窗、强制关注公众号、倒计时、任何拦截阅读的东西——**分享页看着像广告，分享者就不再分享**，这比转化率更贵

## 6. 分期（微信化部分）

| 期 | 内容 | 依赖 |
|---|---|---|
| V1 | 链接卡 `<title>` 工程 + 公开页（含 L1 昵称回应、ics）+ 手机验证码登录（替代 L2） | 无外部依赖 |
| V2 | 认证服务号 → 微信一键登录 + JS-SDK 卡片精细化 + 模板消息（留存） | 服务号认证（企业/个体户主体） |
| V3 | 小程序（原生分享卡 + 订阅消息） | §4 触发条件 |

## 7. 成功指标（微信语境）

- 群分享占比（组局楔子是否成立，>40% 说明打中了）
- 回应率（邀请页 >30%）、卡片点击率（>10%）
- 分享页 → 注册转化（L2 上线前后对比，验证微信登录价值）
- NPS 式问题：分享者"下次还会分享吗"
